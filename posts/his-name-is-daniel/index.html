His Name is Daniel

open-source philosophy curl heroes

Every note2cms publish begins with curl.

Not metaphorically. Literally. The first client anyone uses to test the protocol is curl. The documentation shows curl commands. The iOS Shortcut is curl with a GUI. The Obsidian plugin is curl with a better editor. Every client that will ever be built for note2cms is a wrapper around what curl does natively in one line.

And when someone dismisses this architecture – “it is just a curl command to an endpoint” – they are accidentally describing the highest compliment the system can receive. Because curl is the most installed software on earth. And the man who built it has been refining it for twenty-eight years from a home office south of Stockholm.

His name is Daniel Stenberg. Say his name.

300 Lines of C

In 1996, Daniel wrote a small tool to fetch currency exchange rates from a website. It was called httpget. It was 300 lines of C. He did not have world-conquering ideas. He did not have a business plan. He did not have venture capital. He had a problem – he wanted to see exchange rates in his terminal – and he wrote the minimum code that solved it.

The tool grew. It learned FTP. He renamed it urlget. It learned more protocols. He renamed it curl. It learned HTTPS, IMAP, SMTP, LDAP, MQTT, and twenty other protocols. The 300 lines became 172,000 lines. But the core idea never changed: transfer data from a URL. That is what curl does. That is all curl does.

Twenty billion installations. Every iPhone. Every Android phone. Every Linux server. Every smart car from twenty-two major brands. Every IoT device with a network connection. Every copy of Windows since Windows 10. Every macOS installation. Every PHP runtime. Every Docker image. Every CI/CD pipeline. Every developer’s terminal.

Twenty billion installations of a tool that started because a Swedish programmer wanted to see currency exchange rates.

The Ultimate Dinosaur

Daniel Stenberg is the purest example of the engineer who refined.

He has been the lead developer of curl for twenty-eight years. The same project. The same core mission. Transfer data from URLs. He did not pivot to a platform. He did not start a SaaS. He did not raise funding. He did not build an enterprise edition. He did not even change jobs to work on something more exciting – he changed jobs to work on curl full-time.

From IBM to Mozilla to wolfSSL – each move was made to spend more time on curl, not less. He is now paid to do what he did for free for two decades: refine curl. Fix bugs. Improve error messages. Add protocol support. Make transfers faster, more reliable, more correct. The same tool, getting imperceptibly better every day, for twenty-eight years.

He received the Polhem Prize – Sweden’s highest technical innovation award. The Royal Swedish Academy gave him their Gold Medal. He was named European Open Source Achievement Award winner. Developer of the Year. Microsoft MVP. GitHub Star. Five Google Open Source bonuses. Every institution that recognizes technical excellence has recognized Daniel.

And he still sits in his home office in Huddinge, south of Stockholm, streaming curl development on Twitch, fixing bugs, reviewing patches, and answering questions from strangers on the internet about how to make an HTTP request.

The Most Dismissed Tool

The industry’s relationship with curl is schizophrenic.

Every developer uses it. Every tutorial starts with it. Every API documentation includes curl examples. Every debugging session reaches for it. When something is broken and you need to know if the server is responding, you do not open Postman. You do not write a Python script. You type curl -v and read the headers.

And yet. When someone builds a system where curl is the primary client – where the entire publishing workflow is a single curl command – the industry calls it primitive. “You cannot expect users to use curl.” “That is a developer tool, not a user tool.” “Where is the dashboard?” “Where is the GUI?”

The tool that twenty billion devices trust to transfer data is somehow not good enough for a blog post. The tool that powers the internet’s infrastructure is somehow not suitable for the internet’s content. The tool that Daniel has refined for twenty-eight years until it handles every edge case, every protocol quirk, every network condition – that tool is dismissed as “just a command-line utility.”

note2cms does not dismiss curl. note2cms treats curl as the first-class client it always was. The publishing command is:

One command. One line. The same tool that fetches web pages, tests APIs, downloads files, and transfers data across twenty-six protocols – now publishes a blog post. Not as a workaround. Not as a developer shortcut. As the canonical client. The documentation does not apologize for using curl. The documentation celebrates it.

The Refinement

Daniel’s curl is the ultimate proof that refinement beats expansion.

He could have built a web browser. He had the HTTP stack. He had the TLS integration. He had the cookie handling. He had every component needed to render web pages. He chose not to. He chose to make curl the best transfer tool instead of an adequate browser.

He could have built an API platform. Postman makes hundreds of millions in revenue doing what curl does with a GUI on top. Daniel could have added a graphical interface, a collaboration layer, a cloud sync feature. He chose not to. He chose to make curl the tool that Postman is built on top of.

He could have built a framework. libcurl is used as the HTTP engine inside countless applications. He could have expanded it into a full application framework with routing, middleware, and request handling. He chose not to. He chose to keep libcurl as a transfer library that other frameworks build upon.

Every feature he did not add is a boundary he maintained. Every expansion he refused is a composition he enabled. curl does one thing, and because it does one thing, it composes with everything. It is the universal connector. The tool that fits between any two systems because it has no opinions about what those systems do.

Twenty-eight years of saying no. Twenty-eight years of fixing bugs instead of adding features. Twenty-eight years of making the same tool better instead of making a different tool. The contribution graph does not capture this. The changelog does not celebrate this. But twenty billion installations testify to it.

The Parallel

When I built note2cms, I did not think about curl. I thought about publishing a blog post without opening a browser. The solution happened to be an HTTP POST with a JSON body – which is what curl was born to do.

The alignment was not designed. It was inevitable. When you strip a problem down to its minimum – transferring a payload from point A to point B – you arrive at the tool that has been solving that exact problem since 1996. note2cms did not choose curl. note2cms chose simplicity, and simplicity led to curl.

Daniel did not build curl for note2cms. Daniel built curl for currency exchange rates in 1996, and then refined it until it could transfer anything to anywhere. note2cms is one of twenty billion use cases. But it might be the one that honors curl most directly – because note2cms does not wrap curl in an abstraction. It does not hide curl behind an SDK. It says: curl is the client. The command-line tool that Daniel built is the interface. The thing he has been refining for twenty-eight years is the thing you type to publish your words to the internet.

The Community of Quiet Giants

Daniel belongs in the same community as Sebastian and Armin and Tom and Samuel and Charlie and Guy Steele. The community of people who build small things, refine them for decades, and watch the world build on top of them without asking for credit.

curl is in twenty billion devices and most people do not know Daniel’s name. Jinja2 renders templates across the entire Python ecosystem and most people do not know Armin’s name. FastAPI powers thousands of production APIs and most people do not know Sebastian’s name. These are the people who built the internet’s plumbing and never sent an invoice.

note2cms is plumbing too. Four endpoints. A thin pipe between a notes app and a static host. It will never be as important as curl. Nothing will be as important as curl. But it follows the same ethic: do one thing, do it well, refine it, and do not pretend it is more than it is.

Daniel started with 300 lines of C and a desire to see exchange rates. I started with four endpoints and a desire to publish without opening a browser. Both tools do one thing. Both tools use curl.

Say His Name

The next time someone demonstrates an API, they will use curl. The next time someone debugs a server, they will use curl. The next time someone writes documentation, the examples will be in curl. The next time someone publishes a blog post through note2cms, the command will start with curl.

And none of them will think about Daniel. None of them will think about twenty-eight years of refinement. None of them will think about the home office in Huddinge where a Swedish programmer streams development on Twitch and fixes bugs in a tool that runs on twenty billion devices.

The tool is invisible because it is perfect. The creator is invisible because the tool is. That is the highest compliment and the deepest injustice of open source. The best tools disappear into the infrastructure. The best creators disappear with them.

His name is Daniel Stenberg. He built the tool you use every day without thinking. He has been refining it since 1996. He will be refining it tomorrow. He received a gold medal from a royal academy and he is still fixing bugs in a home office in a suburb of Stockholm.

Every note2cms publish begins with what Daniel built.
